## 🚀 写作流程优化

### 优化前流程

```
1. 打开 CLAUDE.md（内容冗长，难定位）
2. 凭感觉写作
3. 写完后不知道更新什么
4. 容易遗漏设定
```

### 优化后流程

```
1. 打开 07_执行系统/写作启动检查单.md
2. 按步骤完成写作前检查（10 分钟）
3. 写作（实时检查）
4. 打开 08_质量系统/自检模板.md 自检
5. 打开 07_执行系统/更新检查清单.md 更新文件
6. 完成！
```

**优化效果**：
- 写作前：有明确检查步骤
- 写作中：有实时检查标准
- 写作后：有自检模板 + 更新清单

## 💡 核心设计理念

### 1. 单一事实来源（Single Source of Truth）

- 伏笔状态 → 以 `伏笔系统.md` 为准
- 当前剧情状态 → 以 `剧情状态机.md` 为准
- 全局导航 → 以 `卷索引.md` 为准

### 2. 检查清单化（Checklist）

- 写作前 → `写作启动检查单.md`
- 写作后 → `自检模板.md`
- 更新文件 → `更新检查清单.md`

### 3. 可追踪（Trackable）

- 冲突追踪表
- 爽点追踪表
- 人物状态追踪表
- 敌人击杀记录表
- 功法获取追踪表
- 时间线追踪表

### 4. 快速查阅（Quick Reference）

- `CLAUDE.md` 顶部快速索引
- `写作快速参考卡.md` 核心规则速查
- `项目总览.md` 项目状态速查

## ⚠️ 使用注意事项

### 1. 避免过度依赖

- 文件是工具，不是束缚
- 如果某个检查项影响创作流畅度，可以跳过
- 定期复盘，移除不实用的检查项

### 2. 保持更新

- 每章写作后必须更新规则文件
- 每卷结束后复盘，优化追踪表
- 发现设定冲突时，优先更新设定文件

### 3. 适度简化

- 如果觉得检查项太多，可以合并
- 如果某个追踪表长期不用，可以删除
- 框架是为人服务的，不是人为框架服务
